# 第一轮安全加固：HTTP 过渡版本

本轮保留现有眼镜通信和业务逻辑，不需要更换 APK。

已加入网页接口登录检查、写请求 CSRF 校验、管理员登录频率限制（单进程、每来源地址五分钟五次）、安全响应头。默认关闭调试接口、测试身份入口、旧 derived HTTP 接口；历史数据不删除。关闭独立 8081 入口和 /static-videos/ 直接文件路径，视频仍通过现有眼镜 API 播放。

HTTPS 域名、证书目录见 deploy/security.env.example，暂为空。该文件不会自动加载，也不会自动建立 TLS 监听。CHEM_REQUIRE_HTTPS 和 CHEM_REQUIRE_DEVICE_AUTH 默认关闭；设备认证必须等 HTTPS、凭据发放及眼镜端适配完成后再开启。

注意：这不是全部漏洞修复完成。HTTP 仍可能泄露传输中的登录信息、照片和录音；眼镜 API 暂时仍没有设备凭据保护，包括演示视频读取。过渡阶段仅在可信校园网/受限网络使用，不应对公网开放。不要将占位配置当作 HTTPS 已启用。

Docker 内 Flask 仅内部暴露 5080，由 Nginx 转发；CHEM_TRUST_PROXY=1 只适用于这套隔离部署，禁止给 Flask 增加宿主机端口映射。Nginx 覆盖转发来源头，访问日志不记录查询串。

上线步骤：先备份 .env 和 runtime_assets；同步到 code 并生成部署包；按现有安全解压流程更新服务器并重建容器。不要删数据、不要删除卷。此次本地合并不等于线上部署。

验收：登录页可打开；匿名访问 /admin/api/feedback 和 /admin/api/demo/videos 返回 401；调试 /pipeline 返回 404；旧 /teacher-admin/api/derived/ 路径返回 410；管理员和门户登录后可正常使用工作台；现有眼镜上传、分析和视频播放需实机复测；重建后检查 8081 不再监听。HTML 表单及脚本应刷新后再使用，旧网页缓存可能缺少新的 CSRF 令牌。

后续 HTTPS 上线前应配置真实可信证书、稳定随机会话密钥，完成眼镜端设备凭据适配，再启用严格检查。不得为了让设备连接而跳过证书校验。
