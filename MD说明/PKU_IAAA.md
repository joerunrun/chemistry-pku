# 北京大学门户认证返回信息

## 当前认证流程

1. 浏览器跳转到北京大学统一认证。
2. 门户认证成功后返回短期 `token`。
3. 化小北后端把短期 `token` 发往北大校验接口。
4. 北大校验成功后返回 `userInfo`。
5. 化小北以 `identityId` 匹配本地用户，并创建自己的登录会话。

短期 `token` 只用于当次校验，不写入数据库。完整 `userInfo` 原样保存在本地身份库的 `profile_json` 中，便于确认北大实际返回了哪些字段。

## 实测 userInfo 字段

本次学生账号实测共返回以下 9 个字段。个人姓名和学号在文档示例中脱敏；程序数据库保存的是门户实际返回值。

| 字段 | 本次实测示例 | 含义 |
|---|---|---|
| `campus` | `燕园` | 所属校区 |
| `dept` | `物理学院` | 所属院系名称 |
| `deptId` | `00004` | 所属院系编号 |
| `detailType` | `本专科学生` | 更详细的人员类型 |
| `identityId` | `23******66` | 北大身份唯一编号；当前用于本地账号匹配 |
| `identityStatus` | `在校` | 在校/身份状态 |
| `identityType` | `学生` | 门户给出的身份类别 |
| `name` | `已脱敏` | 姓名 |
| `status` | `开通` | 门户账号状态 |

对应 JSON 结构：

```json
{
  "campus": "燕园",
  "dept": "物理学院",
  "deptId": "00004",
  "detailType": "本专科学生",
  "identityId": "23******66",
  "identityStatus": "在校",
  "identityType": "学生",
  "name": "已脱敏",
  "status": "开通"
}
```

教师账号也实测返回相同的 9 个字段：

| 字段 | 教师账号实测示例 |
|---|---|
| `campus` | `燕园` |
| `dept` | `人工智能研究院` |
| `deptId` | `00225` |
| `detailType` | `在职` |
| `identityId` | `20******17` |
| `identityStatus` | `在校` |
| `identityType` | `职工` |
| `name` | `已脱敏` |
| `status` | `开通` |

这里的 `identityType: 职工` 会自动进入教师工作台。

## 当前使用范围

`identityId` 用于稳定匹配本地账号，`identityType` 和 `detailType` 用于首次自动判断角色：

- 两个字段中任意一个包含“学生”，角色为学生。
- 其余值（包括“职工”“教师”和未知类型）默认按教师处理。
- 不再让用户首次登录时自由选择角色，也不再进入旧的角色选择页。
- 管理员可在统一工作台把身份改为学生或教师。管理员设置的优先级高于门户判断，后续再次门户登录不会覆盖。
- 管理员选择“恢复门户判断”后，系统重新采用最近一次保存的门户角色。

眼镜编号仍按每次课程的实际使用时间认领，不与个人永久绑定。

除上述字段外，其余门户字段目前只保存和展示，不参与数据绑定。后续如需自动显示姓名、院系统计或核验在校状态，再单独增加规则。
