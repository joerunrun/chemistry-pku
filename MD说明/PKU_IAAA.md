# 北京大学门户认证返回信息

## 当前认证流程

1. 浏览器跳转到北京大学统一认证。
2. 门户认证成功后返回短期 `token`。
3. 化小北后端把短期 `token` 发往北大校验接口。
4. 北大校验成功后返回 `userInfo`。
5. 化小北以 `identityId` 匹配本地用户，并创建自己的登录会话。

短期 `token` 只用于当次校验，不写入数据库。完整 `userInfo` 原样保存在本地身份库的 `profile_json` 中，便于确认北大实际返回了哪些字段。

## 2026-08-28 实测 userInfo 字段

本次学生账号实测共返回以下 9 个字段。个人姓名和学号在文档示例中脱敏；程序数据库保存的是门户实际返回值。

| 字段 | 本次实测示例 | 含义 |
|---|---|---|
| `campus` | `燕园` | 所属校区 |
| `dept` | `物理学院` | 所属院系名称 |
| `deptId` | `00004` | 所属院系编号 |
| `detailType` | `本专科学生` | 更详细的人员类型 |
| `identityId` | `23******66` | 北大身份唯一编号；当前用于本地账号匹配 |
| `identityStatus` | `在校` | 在校/身份状态 |
| `identityType` | `学生` | 门户给出的身份类别 |
| `name` | `已脱敏` | 姓名 |
| `status` | `开通` | 门户账号状态 |

对应 JSON 结构：

```json
{
  "campus": "燕园",
  "dept": "物理学院",
  "deptId": "00004",
  "detailType": "本专科学生",
  "identityId": "23******66",
  "identityStatus": "在校",
  "identityType": "学生",
  "name": "已脱敏",
  "status": "开通"
}
```

## 当前使用范围

当前业务逻辑只使用 `identityId` 进行稳定身份匹配。学生/教师角色仍由用户首次进入时在化小北系统内选择；眼镜编号按每次课程时间认领，不与个人永久绑定。

其余字段目前只保存和展示，不参与角色判断、权限判断或数据绑定。后续如需自动显示姓名、院系统计或核验在校状态，再单独评估使用规则。
