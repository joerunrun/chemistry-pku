# 待办任务

## 目标

保留实验原始资料，在此基础上逐层生成可检索、可汇总、可填写的教学应用。任何上层分析都不能覆盖原始文件。

## 全局实验目录

- 当前实验由 `code/pipeline/experiments/specs/*.json` 定义，已有减压蒸馏、常压蒸馏等配置。
- 演示视频上传已经存在，但新增实验和实验下拉选项仍主要依赖代码配置。
- 下一步改为后台可维护的实验目录：实验名称、实验基本信息、操作要求、参考文档、演示视频和启用状态。
- 新增实验不能覆盖旧实验；历史记录继续使用原实验 ID。
- 教师可把没有明确实验的历史记录重新映射到实验目录中的某个实验。

## 基础理解与教学应用

- 增加视频关键帧或音轨分析。
- 总结时自动读取实验基本信息和参考文档，只作为背景知识，不把资料内容冒充为实际操作。
- 根据转写、实验类型和时间生成结构化实验记录草稿，教师确认后才成为正式记录。
- 生成单条记录总结：做了什么、观察到什么、存在什么问题、下一步建议。
- 按设备、实验、关键词和问题类型检索原始资料和转写。
- 补充转写质量检查、失败重试和人工重跑入口。

第三层输出建议单独保存为：

```text
runtime_assets/derived/
├── record_summaries/       # 单条记录总结
├── common_issues/          # 共性问题汇总
├── daily_courses/           # 每日课程内容转述
├── scoped_courses/          # 按用户筛选范围生成的课程转述
├── experiment_reports/     # 实验或班级报告
└── indexes/                # 检索索引和标签
```

每个输出必须记录：输入记录 ID、生成时间、模型/提示词版本、结果状态和人工修改时间。模型结果只作为草稿，涉及成绩或正式教学结论时必须人工确认。

## 眼镜端唤醒交互优化

### 近期目标：按钮入口

- 学生版和教师版都允许单击镜腿按钮直接进入功能选择，不依赖云端语音唤醒。
- 屏幕显示可选功能，使用左右滑动切换、单击确认、双击返回。
- 语音唤醒继续保留，作为免手操作的辅助入口。
- 优先复用学生版已有的按钮菜单和眼镜手势，不改上传、认领及后台数据结构。

### 远期目标：无空档环形监听

- 麦克风持续写入环形缓冲，按固定间隔截取相互重叠的音频片段；上传和 Omni 判断期间不能停止录音。
- 唤醒判断采用带迟滞的非对称状态机：强文字匹配或 Omni 返回 `true` 均可唤醒；文字先到但未匹配时不能提前否决，必须继续等待 Omni，超时后才结束本次判断。
- 一旦进入唤醒状态，旧请求返回的 `false` 不得使系统重新沉睡；只有操作完成、明确退出或超时才回到未唤醒状态。
- 每个判断请求携带递增编号，忽略过期结果；唤醒成功后设置短暂冷却，避免重叠片段重复触发。
- 本地文字匹配只作为快速成功和超时兜底，不覆盖已经收到的 Omni `true/false`。

## 实施顺序

1. 完成眼镜按钮入口。
2. 完善全局实验目录，支持新增实验、参考文档和演示视频管理。
3. 增加历史记录到实验的人工映射。
4. 补充转写质量、失败重试和人工重跑入口。
5. 完成单条实验记录填写、检索和其他报告。
6. 最后考虑无空档环形监听、自动推送和统计看板。

## 更新原则

- 代码更新只替换程序容器，不替换 `runtime_assets/`。
- 不在原始记录目录中写入第三层结果；第三层使用独立目录。
- 删除资料只能通过明确的管理操作，并先备份。
- 每次发布后检查：原始文件数量、最新上传时间、分析队列数量和随机抽样下载。
