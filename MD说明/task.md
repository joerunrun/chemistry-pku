# 当前任务：实验目录、参考资料与可选范围课程总结

## 目标

保留实验原始资料，在此基础上逐层生成可检索、可汇总、可填写的教学应用。任何上层分析都不能覆盖原始文件。

## 三层设计

### 第一层：原始数据层（已实现）

- 保存眼镜上传的原始录音、照片、MP4。
- 同时保存设备 ID、实验类型、开始/结束时间、上传时间和文件信息。
- 教师数据：`runtime_assets/teacher_records/`、`runtime_assets/teacher_photos/`。
- 学生数据：`runtime_assets/user_records/`、`runtime_assets/user_photos/`。
- 每次上传使用日期、时间和随机 ID 建立新目录，不覆盖旧记录。

### 全局实验目录（基础已存在，待扩展）

- 当前实验由 `code/pipeline/experiments/specs/*.json` 定义，已有减压蒸馏、常压蒸馏等配置。
- 演示视频上传已经存在，但新增实验和实验下拉选项仍主要依赖代码配置。
- 下一步改为后台可维护的实验目录：实验名称、实验基本信息、操作要求、参考文档、演示视频和启用状态。
- 新增实验不能覆盖旧实验；历史记录继续使用原实验 ID。
- 教师可把没有明确实验的历史记录重新映射到实验目录中的某个实验。

### 第二层：基础理解层（已实现）

- 录音异步转写，结果写入该记录的 `analysis.json`。
- 照片生成简短画面描述，结果同样写入 `analysis.json`。
- 当前默认模型：七牛通道 `google/gemini-3.5-flash`，由 `MEDIA_ANALYSIS_PROVIDER`、`MEDIA_ANALYSIS_MODEL` 配置。
- 视频目前只保存原文件，不自动转写；后续可增加视频关键帧或音轨分析。
- 任务状态保存在 `runtime_assets/media_analysis_jobs/`，服务重启后会继续排队任务。

### 第三层：教学应用层（时间段报告已实现）

第三层只读取第一、二层，生成新的应用结果，不修改原始媒体和原始转写。

首批应用：

0. **共性问题与指导建议**：教师选择最多 31 天、一个实验、可选眼镜和具体记录，使用至少两条自己的有效转写生成重复问题与建议。
1. **每日课程内容整理（兼容保留）**：旧的单日报告继续作为历史报告显示，不删除、不覆盖。
2. **可选范围课程整理（已实现）**：教师选择最多 31 天、可选实验、眼镜和具体记录；默认勾选范围内全部有效记录。只读取当前教师认领的教师音频，照片、纯视频、未完成转写及他人记录不会进入报告。
3. **实验参考资料上下文**：总结时自动读取所选实验的基本信息和参考文档，只作为背景知识，不把资料内容冒充为实际发生的操作。
4. **实验记录填写**：根据转写、实验类型和时间，生成结构化实验记录草稿；教师确认后才成为正式记录。
5. **共性问题总结**：按实验、班级、时间和设备汇总错误现象、常见疑问和高频操作问题。
6. **单条记录总结**：生成“做了什么、观察到什么、存在什么问题、下一步建议”。
7. **检索与标签**：按设备、实验、关键词、问题类型检索原始资料和转写。
8. **教学报告**：按日期或实验生成可下载的汇总报告，保留生成时间、模型和输入记录。

第三层输出建议单独保存为：

```text
runtime_assets/derived/
├── record_summaries/       # 单条记录总结
├── common_issues/          # 共性问题汇总
├── daily_courses/           # 每日课程内容转述
├── scoped_courses/          # 按用户筛选范围生成的课程转述
├── experiment_reports/     # 实验或班级报告
└── indexes/                # 检索索引和标签
```

每个输出必须记录：输入记录 ID、生成时间、模型/提示词版本、结果状态和人工修改时间。模型结果只作为草稿，涉及成绩或正式教学结论时必须人工确认。

## 实施顺序

1. 固定第一层目录、元数据和备份规则。
2. 完善全局实验目录，支持新增实验、参考文档和演示视频管理。
3. 增加历史记录到实验的人工映射。
4. 日期、实验、眼镜和记录筛选已经接入统一教师工作台。
5. 补充第二层的转写质量、失败重试和人工重跑入口。
6. 再做“单条实验记录填写”、检索和其他报告。
7. 最后再考虑自动推送或统计看板。

## 本阶段验收标准

- 不改变眼镜端录音、上传和 APK。
- 新增实验后可以上传对应视频和参考文档。
- 历史记录可以映射到指定实验。
- 总结可以选择“当天全部”或指定实验、设备、记录范围。
- 报告能显示筛选条件、输入记录 ID、模型和生成时间。
- 原始录音、照片、MP4、`record.json` 和单条 `analysis.json` 不被修改。

## 更新原则

- 代码更新只替换程序容器，不替换 `runtime_assets/`。
- 不在原始记录目录中写入第三层结果；第三层使用独立目录。
- 删除资料只能通过明确的管理操作，并先备份。
- 每次发布后检查：原始文件数量、最新上传时间、分析队列数量和随机抽样下载。

## 当前登录与页面规则

- 唯一用户入口为 `/login`，登录后统一进入 `/workspace`。
- 门户字段包含“学生”时自动进入学生工作台；职工、教师和未知身份默认进入教师工作台。
- 管理员修改的角色不会被下次门户登录覆盖；可以手动恢复门户判断。
- 旧 `/teacher-admin`、`/admin` 等地址只负责跳转兼容。
