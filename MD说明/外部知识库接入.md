在后端 `.env` 配置（不放进 APK，不添加服务器登录密码）：

```dotenv
CHEM_KNOWLEDGE_URL=http://162.105.205.15:8000
CHEM_KNOWLEDGE_TOKEN=实际服务令牌
# 可省略，省略时自动读取可用知识库，最多取20个
CHEM_KNOWLEDGE_IDS=
# 可省略；原文件不是视频时，用此文件补充文档ID到实际播放地址的对应关系

```

只有 `.134` 已获准访问知识库。本机未放行前不启用上述配置；未配置或检索失败时，问答继续使用模型已有知识，本地视频仍可使用。

眼镜接口沿用：

- `POST /api/glasses/qa`，输入 `{"question":"滴定管为什么要润洗？"}`，输出仍为 `{"question":"...","answer":"...","timings":{...}}`。
- `POST /api/glasses/jobs`，沿用图片上传，表单增加 `mode=general_check`、`check_request=用户具体检查要求`；沿用原任务轮询，结果增加 `sources` 记录资料 ID 和标题。没有可用资料时给出有限的照片观察建议并明确说明。
- `GET /api/glasses/demo/videos?q=滴定管润洗`，输出 `{"videos":[...]}`。不带实验分类时搜索全部本地视频；提供搜索词时同时查询外部视频资料。

视频候选示例：

```json
{
  "id": "knowledge:知识库ID:文档ID",
  "label": "滴定管的洗涤",
  "filename": "滴定管的洗涤",
  "source": "knowledge",
  "knowledge_base_id": "知识库ID",
  "document_id": "文档ID",
  "stream_url": "/api/glasses/demo/videos/knowledge/知识库ID/文档ID/stream",
  "playable": true
}
```

外部 `QueryResult` 新增 `is_transcript`：为 true 表示检索命中的是视频转录文字，`content` 仍用于问答和纠错，`download_path` 直接指向原始视频，下载仍需令牌。抽查结果的文档详情 `files.original` 也已同步为 `.mp4`，因此现有模块已能兼容，无需更新眼镜 APK。原视频缺失的条目仍不能标为可播放。

2026-10-20 已将 HEAD 长度修正部署到 `.134`，不再把上游视频长度覆盖为 0。通过 Nginx 抽查上述两段视频，HEAD 返回正确文件长度，开头、末尾 Range 请求均为 206，视频传输接口验证通过；眼镜实际解码和播放仍需实机确认。本次未修改眼镜 APK 发布信息。

视频地址支持两种接法：

1. 外部接口的 `original` 真正返回 `.mp4`：现有框架自动生成后端转发地址，支持 HEAD 和 Range，外部令牌留在后端。
2. 另给可直接访问的播放地址：配置 `CHEM_KNOWLEDGE_VIDEO_MAP` 指向 JSON 文件，例如 `{"实际文档ID":"https://视频服务/实际文件.mp4"}`。眼镜端无需改格式。Docker 使用时该文件需要位于已挂载目录内，环境变量填容器内路径。

如果另给的地址也需要服务端鉴权，或者采用不同的视频接口，只需调整共用模块 `pipeline/common/knowledge_client.py` 的地址适配和转发；不能仅替换一个地址就保证可播放。
