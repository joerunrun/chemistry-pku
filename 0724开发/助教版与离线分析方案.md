# 助教版记录与离线分析

## 当前行为核对

- 助教版进入 App 后立即持续录音：本地写入一个会话 WAV，并维护最近 3 秒的环形缓冲。
- 每 3 秒会把一段临时 PCM 上传到 `/api/glasses/voice/intent`，只用于判断命令；这些临时片段服务端不会保存。
- `LISTENING` 状态当前必须先说“小北助手”。唤醒后才识别“拍照”或“开始记录”。录像状态只判断“结束记录”，不要求再次说唤醒词。
- 主动结束录像时，视频/录音会上传到 `runtime_assets/teacher_records/`；退出助教 App 时，整段持续录音 WAV 也会上传。
- 教师拍照当前只保存到眼镜本地，回调没有上传；教师记录虽存到 `teacher_records/`，但现有 `/admin` 只列学生 `user_records/` 和 `user_photos/`，因此教师内容目前不能从前端查看。

## 目标改造

1. 教师照片增加上传，保存到 `runtime_assets/teacher_photos/<日期>/<photo_id>/`；原始文件永不被分析任务覆盖。
2. 教师前端独立为 `/teacher-admin`，只读取教师的照片和记录；学生 `/admin` 保持只读学生目录。
3. Nginx 使用不同端口代理同一后端：学生例如 `80`，教师例如 `8081`。端口分开只隔离入口，不构成访问控制；正式使用仍应加校园网 IP 白名单或登录。
4. 每次原始音频或图片上传后立即返回成功，并写入持久化任务状态：`queued/running/succeeded/failed`。后台 1--2 个 worker 慢速处理，服务重启时扫描 `queued/running` 任务继续处理。
5. 只离线分析音频和图片：
   - 音频：Gemini 转写，保存 `transcript`。
   - 图片：Gemini 生成一句简洁场景描述，保存 `description`。
   - 视频：仅保存、下载、播放，不做描述。
   - 分析结果保存为同目录 `analysis.json`，前端展示状态、转写和图片描述；眼镜端不等待这些任务。

## 七牛云核对

当前代码默认使用 `QINIU_API_BASE=https://api.qnaigc.com`、`QINIU_API_KEY` 和模型 `google/gemini-3.5-flash`，请求会规范化为 OpenAI 兼容的 `/v1/chat/completions`。

七牛当前文档仍提供国内 `https://api.qnaigc.com`、海外 `https://api.modelink.ai`，并声明 OpenAI 兼容接口；模型目录已经出现较新的 Gemini 2.5 Flash、Gemini 3.1 Pro 等，也列出 `input_audio` 数据结构。已用当前 `.env` 对 `google/gemini-3.5-flash` 做最小文本请求，接口返回“测试成功”，因此当前文本/图片链路仍可用。短 `max_tokens=32` 会被 reasoning token 用尽而得到空文本；后续离线任务不应把输出上限设得过小。音频输入是否受该具体模型支持仍须在接入前实测。不要把 API Key 写进前端或 APK，只放服务器 `.env`。

## 实施顺序

1. 教师照片上传与教师独立列表。
2. 持久化离线分析队列及 `analysis.json`。
3. 七牛 Gemini 音频、图片两类最小实测后写入模型配置。
4. Nginx 增加教师管理端口与访问控制。
